1. Overview & Multi-Portal Architecture

AuraMarket is a modern, high-concurrency multi-vendor e-commerce marketplace engineered with Node.js, Express, MongoDB, React 18, and Flutter.

The platform is architected around 4 isolated business portals in a unified monorepo:

Portal Target Persona Core Responsibilities
Customer Storefront (Web & PWA) End Shoppers Dynamic catalog search, category filters, multi-vendor cart splitting, address checkout (COD & UPI), real-time order tracking, and 4-digit handover OTP.
Super Admin Control Center Platform Owner Gross sales analytics, platform commission fee controls, vendor KYC verification/suspension, double-entry financial ledger, and 1-click showroom demo wipe/seed.
Vendor / Merchant Central Third-party Sellers Product catalog management with multi-variant SKUs, store-specific order fulfillment packing slips, status steppers, and instant wallet bank payout requests.
Courier & Logistics Hub Delivery Fleet / Riders Field task assignment, warehouse pickup navigation, COD cash collection, and mandatory 4-digit OTP verification upon customer handover.
Cross-Platform Mobile Apps Shoppers & Delivery Native Flutter 3.x codebase for Android (Release APK) and iOS with seamless REST API sync and offline caching.

2. System Requirements

Ensure your development and production environments meet these standard specifications:

  • Node.js: Version 18.x or 20.x LTS (Recommended)
  • Database: MongoDB 6.0+ (Local MongoDB Community Server or free MongoDB Atlas Cloud cluster). Note: Backend also includes a zero-dependency In-Memory MongoDB engine for instant showroom demonstrations.
  • Package Manager: npm v9.x+ or yarn v1.22+
  • Flutter SDK (Optional for mobile apps): Flutter 3.19+ and Dart 3.3+ with Android SDK tools.
  • Web Server (Production): Any Linux VPS (Ubuntu 22.04 LTS), Hostinger, cPanel, Apache, Nginx, or Docker.

4. Backend Installation & Setup (Node.js + MongoDB)

Follow these quick steps to launch the enterprise API gateway:

Step 1: Install Dependencies

cd backend
npm install

Step 2: Environment Variables (.env)

Create a .env file inside the backend/ folder (or copy .env.example):

PORT=5000
NODE_ENV=development
MONGO_URI=mongodb://127.0.0.1:27017/ecommerce_marketplace
JWT_SECRET=production_grade_super_secret_jwt_key_2026_obsidian_amber
JWT_EXPIRES_IN=7d
CORS_ORIGIN=*
💡 Zero-Configuration Fallback: If MongoDB is not running locally, the backend automatically launches a seamless in-memory database engine and seeds the showroom data so you can test immediately without installing MongoDB.

Step 3: Seed Catalog & Start Server

# Run database seeder (Optional, auto-seeded on first run)
npm run seed

# Start API Server
npm start

Verify that your API is running by opening http://localhost:5000/api/health in your browser.

5. Frontend Installation & Setup (React 18 + Vite)

Launching the modern Tailwind CSS user interface:

Step 1: Install Dependencies

cd frontend
npm install

Step 2: Environment Configuration (.env)

VITE_API_BASE_URL=http://localhost:5000/api

Step 3: Run Development Server

npm run dev

Open http://localhost:3000 to view the full showroom!

Step 4: Build for Production Deployment

npm run build

The compiled production build will be generated in frontend/dist/.

6. Flutter Mobile App Compilation (Android & iOS)

The native Flutter app codebase is located in mobile_app/:

Step 1: Load Flutter Packages

cd mobile_app
flutter pub get

Step 2: Configure API Endpoint

Open mobile_app/lib/services/api_service.dart and set your live API domain:

static const String baseUrl = 'https://yourdomain.com/api';

Step 3: Compile Release APK for Android

flutter build apk --release

Your production APK is ready at: build/app/outputs/flutter-apk/app-release.apk.

9. 4-Digit Secret Delivery OTP System

How AuraMarket prevents delivery fraud and ensures customer satisfaction:

  1. When a customer places an order, the backend generates a cryptographic 4-digit secret delivery OTP (e.g. 4821).
  2. This OTP is displayed only on the customer's order receipt and SMS/WhatsApp confirmation.
  3. Neither the vendor nor the courier rider can see the OTP.
  4. When the rider reaches the customer's doorstep, the customer shares the code.
  5. The rider enters the code into the Courier Hub (/api/delivery/tasks/:id/verify-otp).
  6. Only upon matching does the system update the task to DELIVERED, credit the vendor's wallet, and record the ledger entry. Direct status manipulation without OTP is strictly rejected with HTTP 400!

11. Troubleshooting & Frequently Asked Questions

Common questions and step-by-step diagnostic fixes:

Q: MongoDB connection error on backend startup?

Fix: Ensure your local MongoDB service is running (net start MongoDB on Windows, or sudo systemctl start mongod on Linux). Alternatively, provide your MongoDB Atlas Cloud connection string in backend/.env. The server will also automatically initiate in-memory mode if external MongoDB is unreachable.

Q: How do I change the currency symbol?

Fix: The default currency is formatted in Indian Rupee (₹) or USD ($). You can easily update the currency formatter in frontend/src/utils/formatters.js or CustomerStorefront.jsx.

Q: Can I run this with Docker?

Fix: Yes! A docker-compose.yml file is provided in the root directory to spin up the entire stack with a single docker compose up command.
